# 高负载 (CPU 100%) 下快速滚动消息区严重掉帧、卡顿与操作粘滞

**状态**：Open
**优先级**：中
**创建日期**：2026-10-28
**GitHub Issue**：#768 (https://github.com/cc-claws/cc-code/issues/768)

## 问题描述

在系统 CPU 处于高负载（接近或达到 100%）时，在 TUI 消息区域使用鼠标滚轮快速上下滚动或通过按键翻页，界面出现严重的掉帧、停顿与操作粘滞感。表现为手指停止滚动后画面仍在滞后逐帧跳动补移，期间键盘输入响应极慢甚至短时间失去响应。

## 症状详情

1. **画面掉帧与滞后补帧**：在多轮历史消息会话中，当后台有高 CPU 消耗任务（或系统负载满）时，快速拨动鼠标滚轮，视口并没有平滑跟随，而是卡顿数帧后突然跳跃，滚轮停止后仍持续滚动补齐。
2. **输入响应粘滞**：滚动过程中尝试按快捷键或输入字符，按键事件被严重延后处理，甚至引发界面假死。
3. **低负载与高负载对比明显**：在 CPU 空闲时，消息区滚动相对顺畅；但在 CPU 满载时滚动体验急剧恶化，滚轮重绘的耗时被无限放大。

## 复现条件

- **复现频率**：高负载场景下必现
- **触发步骤**：
  1. 启动 TUI 并打开一个具有一定历史消息量（数轮问答或包含工具输出）的会话。
  2. 在后台制造 CPU 高负载（例如并发编译、运行密集计算任务使 CPU 占用接近 100%）。
  3. 在消息区域快速上下滑动鼠标滚轮或连续使用 PageUp/PageDown 浏览历史。
  4. 观察画面滚动的平滑度、帧率稳定性及对其他输入的响应速度。
- **环境**：
  - OS: Windows 11 (ConPTY / Windows Terminal)
  - 二进制: cc-code TUI

## 涉及文件

- `cc-tui/src/main.rs` —— 主事件循环中 `Action::Redraw` 的帧率门控与重绘调度逻辑
- `cc-tui/src/event/mod.rs` —— 鼠标滚轮与键盘事件批处理及分发链路
- `cc-tui/src/ui/main_ui/message_area.rs` —— 视口裁剪（`viewport_clip`）及 `render_cache` 锁交互
- `cc-tui/src/ui/render_thread.rs` —— 渲染线程的换行测算与背景行缓存管理

## 期望改进方向

1. 引入交互重绘帧率节流（如类似 loading 的 TARGET_FRAME_INTERVAL 或滚动合批门控），防止高频滚轮事件风暴导致无节制连续重绘。
2. 优化滚动时的读锁等待策略，避免 UI 主线程因等待后台渲染锁而完全阻塞。
