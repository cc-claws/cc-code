# PRD：紧凑启动与随内容增长的终端视口

日期：2026-10-21

版本：v1.2（人工反馈与退出清理修正）

GitHub Issue：[#650](https://github.com/cc-claws/cc-code/issues/650)；[初版 PRD 快照](https://github.com/cc-claws/cc-code/issues/650#issuecomment-6309673586)；交互修正以本稿 v1.2 为准。

状态：人工反馈问题已修正，自动化验证通过；用户已确认 Windows 终端人工验证无问题，macOS/Linux 兼容性检查待完成。

适用范围：`cc-tui` 交互模式。

视觉依据：[已确认的 HTML 交互稿](../designs/2026-10-21-growing-terminal-preview.html)。

## 1. 背景与目标

改动前启动 `cc-code` 即进入全屏终端，欢迎页占满可用高度，输入框直接落在屏幕底部。用户希望启动像普通 CLI 一样，只显示少量必要内容；输入与回复逐步增加时，界面再向下展开，长满后使用全屏交互。

目标体验：**紧凑启动 → 按内容增长并滚动必要行数 → 长满整个宿主高度后全屏固定**。

这里的“长高”指应用占用的终端行数增加，宿主终端窗口的尺寸保持不变。

### 1.1 已确认的主流程

| 编号 | 需求 |
|---|---|
| R01 | 启动只显示紧凑欢迎卡、输入框和状态栏，不立即清空或占满终端 |
| R02 | 欢迎卡从当前 shell 启动位置下方排版，不垂直居中 |
| R03 | 输入、消息、思考和工具结果增加时，占用区域逐步向下增长 |
| R04 | 增长阶段输入框跟随内容向下移动，状态栏紧随输入框 |
| R05 | 每次增长时原生滚动必要行数并上移视口起点；内容或已占用高度达到整个宿主高度后才锁定全屏 |
| R06 | 切换后输入框固定在底部，消息区内部滚动；输出折叠或回复结束都不缩回 |
| R07 | 紧凑欢迎卡作为纯 UI 前缀跨首条消息与全屏切换保留，并随消息一起滚动 |

### 1.2 本 PRD 补充规则的确认范围

本次实现采用第 5 节边界规则，包括新建会话保留已占用高度、每次增长最小滚动、普通面板按真实终端测量及外部编辑器恢复原模式。2026-10-21 首轮人工反馈明确修正了全屏后欢迎卡退场、按起点以下余量提前切全屏和切屏闪烁三处行为；后续反馈进一步要求退出清除正常屏应用界面，仅留下会话恢复提示和 shell 提示符。本稿以修正后的规则为准，反馈与复测入口见第 8.4 节。

## 2. 范围

本次交付包括紧凑欢迎卡、启动视口、增长高度计算、全屏切换及相关终端生命周期适配。保留现有消息渲染、工具输出样式、主题、权限模式、命令、快捷键和 ACP 通信契约。

本次不处理 `Glob/Grep` 收到 `command` 参数的问题，也不调整模型行为、token 统计口径、版本更新检查或安装渠道。

HTML 中的阶段按钮、自动播放、右侧说明、占用进度、增长边界线和模拟发送按钮只用于预览，不进入真实 TUI。示例中的模型名、版本、配置路径、配置字段及统计数字不构成功能需求，真实界面使用现有数据来源。

## 3. 布局与交互

### 3.1 阶段一：紧凑启动

```text
已有 shell 输出
❯ cc-code

╭────────────────────────────────────────────╮
│  小型吉祥物   CC Code  v<实际版本>          │
│               <当前工作目录>               │
│               开始对话，或 /help 查看命令   │
╰────────────────────────────────────────────╯
──────────────────────────────────────────────
❯ 光标
──────────────────────────────────────────────
[模型] 上下文 | 项目 git:(分支) | 统计
权限模式 · Agent · Cache · MEM

下方尚未使用的终端空间
```

- 欢迎卡靠左放置，宽度随终端适配，不横向拉伸为整屏大卡片。
- 内容只保留品牌与实际版本、工作目录、一条开始使用提示，以及空间允许时的小型吉祥物。
- 使用当前主题配色。窄屏先省略装饰，再对长路径按显示列宽省略，保留标题与输入入口。
- 移除启动区域的大字 Logo、长功能列表及垂直居中留白；其他帮助信息通过现有命令获取。
- 输入框保持现有边框和编辑行为；状态栏保持现有空闲 2 行、有活动 3 行规则。
- 常规单行输入下，整块启动界面目标约 10～12 行，实际以字体单元格、必要引导和状态栏为准；不得按终端高度比例主动放大欢迎卡。
- 无 Provider 时保留简短的 `/login` 配置引导，不以展示完整功能列表为由扩大欢迎区。

### 3.2 阶段二：按内容增长

- 用户输入换行、消息发送、流式回复、工具结果或附件加入，均可增加所需高度。
- 所有可见内容从上向下连续排版，输入框及状态栏位于内容末尾。
- 欢迎卡继续作为纯 UI 前缀存在，首条消息及全屏切换均不使其消失；与消息共用滚动偏移和裁剪，不固定悬挂在消息区上方。
- 以当前折叠状态和实际换行后的视觉行数计算高度。工具隐藏全文、未展示的推理内容不计入高度。
- 相同终端尺寸下，只在所需高度超过已占用高度时扩展。工具完成、思考提示退场、删除输入或折叠结果均不主动缩小占用区域。
- 内容减少后，允许消息末尾出现少量空白，输入区保留已达到的位置，避免上下跳动。
- 持续流式输出按现有刷新节奏推进，不逐 token 修改终端模式，不加入延迟输入的高度动画。HTML 的过渡动画仅用于演示。
- 输入框仍遵守现有多行上限和内部滚动规则；状态栏及工具头部长文本保持现有单行省略。

### 3.3 阶段三：满屏固定

- 切换发生在绘制前：当内容或已占用高度达到整个宿主高度时，直接绘制全屏结果，不先画出越界帧。仅起点以下余量不足时继续原生滚动必要行数并上移起点，不能提前全屏制造大量留白。
- 切换后使用底部固定输入的全屏布局，欢迎卡仍作为纯 UI 前缀随消息滚动，原 shell 内容不在当前应用视图中展示。
- 切换前先等待目标宽度重排完成，切屏、resize 与首帧同步输出，合并重复清屏，不在进入空白 alternate screen 后等待排版。
- 消息内容、未发送草稿、附件、队列、工具状态、审批选择和当前焦点均保留。
- 输入区固定在底部布局中；其上方的附件、队列、面板按现有规则占位。
- 消息超出可用高度后，沿用现有滚动条、跟随底部、返回底部、选区与链接行为。
- 正常跟随输出时，切换后仍显示最新内容；用户已主动离开底部时保留对应消息锚点。
- 全屏切换只发生一次，不随内容高低在两种模式之间反复切换。

## 4. 高度与切换判定

所有尺寸以**终端显示列与行**为单位，禁止使用字符数或 HTML 像素作为真实终端高度依据。

| 变量 | 含义 |
|---|---|
| `terminal_rows` | 当前宿主终端可见行数，不含窗口标题栏 |
| `origin_row` | 紧凑视口起始行，使用真实终端坐标，首行是 0 |
| `available_rows` | 从视口起点到底部的行数：`terminal_rows - origin_row` |
| `required_rows` | 下一帧所有可见区域实际需要的总行数 |
| `allocated_rows` | 增长阶段已经分配的高度 |
| `fullscreen_latched` | 是否已锁定为全屏模式 |

```text
required_rows = 欢迎卡行数（纯 UI 前缀，跨全屏保留）
              + 消息视觉行数
              + 思考 / 总结 / Todo 等附属行数
              + 附件、面板、待发队列行数
              + 输入框、状态栏、后台栏行数
              + 实际使用的边框与间距行数

next_rows = max(allocated_rows, required_rows)

若 fullscreen_latched：使用当前全屏布局
否则若 next_rows >= terminal_rows：切换并锁定全屏
否则：
  scroll_rows = max(0, origin_row - (terminal_rows - next_rows))
  原生滚动 scroll_rows 行
  origin_row -= scroll_rows
  available_rows = terminal_rows - origin_row
  使用 next_rows 高度的增长视口
```

欢迎卡高度始终作为 UI 前缀参与测量、消息滚动和裁剪，不写入历史、系统提示词或消息渲染缓存。`available_rows` 只描述当前起点以下余量，不作为全屏阈值；例如 `24` 行终端底部启动后从 `11` 行增长到 `12` 行，只原生滚动 `1` 行，长到 `24` 行才锁定全屏。

复用消息渲染缓存中的视觉行数；终端宽度变化时，先取得对应宽度的排版结果，再作高度判定。不得将整屏可用行数或上一帧分配的空白重新计为“新增内容”，造成空闲状态自动长高。

弹出面板的所需高度应以真实终端尺寸和现有面板规则为依据，不能因当前紧凑视口较矮而反复压低面板高度。

## 5. 边界行为：首版实现规则

| 场景 | 行为 |
|---|---|
| 启动光标靠近底部 | 首帧及后续增长均仅滚动必要行数并上移起点；内容或已占用高度未长满整个宿主前不触发全屏 |
| 启动时下方余量很少 | 不清空整个终端制造留白，不按起点以下余量提前全屏；增长继续占用原生滚动释放的空间 |
| 终端连最小启动界面也放不下 | 直接使用全屏布局，省略装饰并保留可操作输入区；极小尺寸不得 panic 或发生坐标下溢 |
| 窄屏、中文、emoji、长路径 | 按显示列宽换行或省略；不拆 UTF-8 字符；装饰可隐藏 |
| 放大终端 | 增长阶段保留已占用高度，不填充新增空白；全屏阶段继续全屏，不退回增长阶段 |
| 缩小终端 | 先重新换行并计算；仍低于宿主高度时滚动必要行数上移起点，达到宿主高度才锁定全屏；已经全屏时按现有规则重排 |
| 打开普通设置、审批或提问面板 | 计入实际所需高度；能容纳则增长，否则全屏。关闭面板后不缩回，已有审批选择和焦点保留 |
| 首次配置向导、Agent Center 等现有全屏界面 | 进入该界面时锁定全屏，关闭后继续全屏，不额外设计紧凑版 |
| `Ctrl+O` 展开长输出 | 按展开后的行数增长或触发全屏；再次折叠不缩回 |
| 回复结束、报错或用户中断 | 只结束对应任务或显示错误，不重置视口阶段、草稿和消息 |
| 增长阶段 `/clear` 新建会话 | 清理会话内容，重新显示紧凑欢迎卡，但保留已占用高度 |
| 全屏阶段 `/clear` 新建会话 | 继续全屏，空会话使用紧凑欢迎内容，不恢复旧的大字居中欢迎页 |
| 恢复历史会话 | 按恢复后的内容直接选择增长或全屏；不先闪现空欢迎页；有历史消息时不补插启动欢迎卡 |
| 子 Agent 视口切换 | 按目标视口的实际内容高度计算；不会因切回较短内容而缩回 |
| 打开外部编辑器 | 挂起前记录终端模式；关闭编辑器后恢复同一模式、视口起点和内容。编辑器临时使用全屏不等于应用已锁定全屏 |
| 增长阶段退出 | 恢复光标、raw mode、鼠标和标题等宿主状态，逐行清除应用拥有的正常屏区域，光标回到该区域起点，仅留下 Session ID、Resume 和 shell 提示符；不清除其上方 shell 历史 |
| 全屏阶段退出 | 先成功离开 alternate screen，再清除进入全屏前的正常屏应用区域；全屏绘制不得覆盖该区域记录。清理成功后消费记录，显式恢复与 Drop 重复调用不擦除退出提示 |

建议 `fullscreen_latched` 属于本次终端运行实例：新消息、`/clear`、恢复历史和切换视口均不重置；退出程序后重新启动才重新进行初始判定。该状态不写入持久化会话，不影响模型上下文。

## 6. 实现约束与影响面

以下是基于当前本地代码的落点建议，不指定必须采用哪一种 Ratatui 视口 API。实现前应验证动态增长、原生终端滚动和 alternate screen 切换的可行性。

| 位置 | 当前行为 / 需要覆盖的调整 |
|---|---|
| `cc-tui/src/main.rs` | 启动立即进入 alternate screen 并创建全屏 Terminal；需要按阶段初始化、分配高度、切换、重绘和退出恢复 |
| `cc-tui/src/ui/welcome.rs` | 当前欢迎内容垂直居中；改为紧凑卡片并提供与渲染一致的高度测量，保留可用的吉祥物资源 |
| `cc-tui/src/ui/main_ui/mod.rs` | 消息区填充剩余空间；需要接收真实视口区域，共用底部各区域的高度计算 |
| `cc-tui/src/ui/main_ui/message_area.rs` | 当前仅空消息时显示 welcome；需要区分启动欢迎卡与正常消息，避免首条消息后提前消失 |
| `cc-tui/src/ui/render_thread.rs` | 已有 `RenderCache.total_lines`、宽度与换行映射；优先复用，保持高度计算与实际渲染一致 |
| `cc-tui/src/event/`、鼠标与选区处理 | 增长视口起点可能不是 `(0,0)`；命中、复制、链接、拖拽均使用同一套真实坐标 |
| `cc-tui/src/app/panel_memory.rs` | 当前外部编辑器返回后直接进入 alternate screen；需要恢复挂起前的模式 |
| `cc-tui/src/terminal_backend/` | 配合终端尺寸、光标定位、原生滚动和局部清理，检查 Windows 宽度与 VT 兼容逻辑 |
| i18n 与 TUI 文档 | 新欢迎提示中英文同步；实现完成后更新 `TUI-STYLE.md` 和对应 TUI 领域文档 |

关键约束：

- 增长阶段只绘制和清理应用拥有的区域，不能用全屏清屏实现每次扩高。
- 物理屏幕切换前完成目标排版；切屏、resize、差分缓存重置及首帧同步输出，合并重复清屏，避免旧内容残影或先清屏等待造成的闪烁。
- 高度、消息换行、光标定位和鼠标命中使用同一份视口尺寸；高度测量不产生额外 LLM 请求或工具调用。
- 不把欢迎卡、视口阶段和终端信息注入消息历史或系统提示词；欢迎卡也不写入消息渲染缓存，以纯 UI 前缀单独计入高度、滚动与裁剪；不改变 frozen system prompt。
- 保持 TUI → ACP 的现有分层，不因 UI 改动在 TUI 层重建 Agent 或事件泵。
- 不覆盖本地已有的无关改动；HTML 演示逻辑不直接作为终端实现复用。

## 7. 验收标准

正常尺寸优先覆盖 `80×24`、`120×40`；窄屏覆盖 `40×24`；极小尺寸验证无崩溃和越界。切换判定另外覆盖实际终端底部临界值。

| 编号 | 操作 / 前提 | 预期结果 |
|---|---|---|
| A01 | 在底部余量充足的 shell 中启动 | 上方历史保留；欢迎卡紧凑靠左；输入框紧邻内容；未使用空间不被绘制为全屏 |
| A02 | 停留空闲，等待多次刷新 | 高度和起点稳定，不自行长高或清屏 |
| A03 | 输入多行草稿，再删除部分内容 | 按显示行数增长；删减不缩回；光标和输入编辑正常 |
| A04 | 发送第一条短消息 | 欢迎卡仍在顶部，与首条消息间隔一行；消息只出现一次；输入区下移；无模型重复提交 |
| A05 | 持续生成回复并返回工具结果 | 随可见内容增长，状态栏紧跟输入区，无大块人为留白或重复绘制 |
| A06 | 所需高度为宿主高度减 1；起点以下余量不足 | 原生滚动必要行数并上移起点，继续增长，内容、输入框、状态栏均可见 |
| A07 | 所需内容或已占用高度等于或大于宿主高度 | 重排完成后同步切屏与首帧，仅切换一次，无空白等待或越界中间帧；欢迎卡跨切换保留并随消息滚动 |
| A08 | 切换时存在草稿、附件、队列或审批选择 | 内容、焦点及状态保留，不丢字、不重复发送、不重置选择 |
| A09 | 全屏后继续输出多个屏幕 | 输入区固定；消息按现有规则滚动和跟随；能滚回历史 |
| A10 | 全屏后折叠工具、结束回复或中断 | 保持全屏，不退回紧凑视口 |
| A11 | 长中文、emoji、长路径与流式换行 | 无乱码、panic、字宽错位；测量高度与实际排版一致 |
| A12 | 增长阶段和全屏阶段缩放终端 | 按第 5 节规则重排；没有输入框越界、状态栏残影和模式反复切换 |
| A13 | 视口起点非 0 时点击、拖选、复制及打开链接 | 命中正确行列，复制文本与可见内容一致 |
| A14 | 打开并关闭短面板、长审批或提问面板 | 选择与快捷键有效；高度足够或切至全屏；关闭不缩回 |
| A15 | `/clear`、恢复历史和切换子 Agent | 按第 5 节规则保持阶段与高度，无空欢迎闪烁、消息丢失或错误视口内容 |
| A16 | 两种模式分别打开外部编辑器并返回 | 恢复原模式与输入，鼠标和终端重绘正常 |
| A17 | 初始光标位于最后几行或终端极矮 | 初始及后续增长均只滚动必要行数；24 行终端中 11→12 行只滚动 1 行而不全屏，达到 24 行才全屏；不可容纳最小布局时稳定退化为全屏 |
