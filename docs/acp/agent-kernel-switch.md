# Agent 内核切换与共享能力

本次审计基于 PR #903 的 `a4f03fb6`，以用户要求为准：切换 cc、dsh、pi 的提示词和工具方言，同时复用用户已有的记忆、Skills、MCP 配置与权限。主 Agent 和子 Agent 继续使用同一项目的共享能力；切换不会创建按内核划分的记忆库或重写用户数据。

## 本轮修复的问题

| 问题 | 修复后的行为 |
| --- | --- |
| pi 隐藏 Skill，已配置的技能无法主动调用 | 三种内核均保留 Skill；dsh/pi 暴露为 `skill`，继续使用同一发现、加载与 fork 执行链路 |
| 提示词混入 cc 工具名与不可用的发现工具 | 仅翻译代码生成的模板；非 cc 内核不注入 cc 的工具发现缓存，MCP 保持原名称与参数 |
| 历史记忆在 `.claude`，读取提示却指向 `.cc-code` | 展示路径跟随实际选中的存储目录，继续读取原有记忆 |
| 模板替换可能改写记忆、技能描述或路径中的字面内容 | 在插入用户数据前渲染模板，保留工具名、路径和 `{{cwd}}` 等字面内容 |
| SQLite 创建线程时遗漏内核身份 | 新建、fork 与子线程创建时保存 `kernel_id`，恢复时优先使用保存的身份 |
| 持久化失败后仍改变当前内核 | 保存失败返回错误并恢复线程身份；成功后才发布内存配置、冻结身份和缓存失效 |
| IDE stdio 入口未完整接入切换与恢复 | 与 TUI 共用持久化、严格解析和提示词渲染；非空历史也会补齐缺失的冻结身份 |
| 配置面板及 `/kernel show` 读全局值，可能与当前会话不同 | 配置选项读取当前会话身份；命令查询后端的实际会话与基础系统提示词 |
| TUI 先保存配置，后台失败只写日志 | 等待后端确认后更新界面，失败原因显示在当前会话，迟到结果不会串入其他会话 |
| pi 嵌套编辑参数冲突可能写入错误内容 | 递归校验嵌套 schema，冲突被拒绝，文件保持原样 |
| pi 批量编辑 CRLF 出现重复回车 | 匹配文本与替换文本先统一换行，再按原文件格式写回 |
| 截断输出提示替换了真实文件路径 | 只翻译工具名与参数名，落盘路径保持原样 |

## 会话检查扩展

TUI 内部传输与 IDE stdio 均支持自定义请求 `session/kernel`：

```json
{"sessionId":"<当前会话 ID>","cwd":"<无会话时使用的项目目录>"}
```

响应示例：

```json
{"kernelId":"pi","scope":"session","systemPrompt":"..."}
```

`scope` 为 `session` 或 `default`。非空且不存在的会话 ID、未知的已保存内核身份均返回错误。`systemPrompt` 与执行时共用基础提示词渲染及内核、Git Attribution 拼装；项目指引、Skills、工具结果和其他中间件消息仍按原执行链路单独注入。它不是整个模型请求的转储。

这是新增扩展，没有移除既有字段。现有 `configOptions` 的 `agent_kernel.currentValue` 改为反映当前会话的冻结身份，前端不应再用全局默认值覆盖它。

## 验证范围

- 使用本地模型端点执行三种内核下的真实 Skill 调用与后续请求，检查共享记忆、用户描述、工具 schema 和原始正文。
- 使用内存管道建立真实 MCP 协议连接，让三个内核复用同一连接池并调用同一工具，检查原始名称、参数与结果。
- 使用文件和 SQLite 存储验证创建、恢复、fork、配置保存失败回滚及其他会话不受切换影响。
- 使用实际 ReAct 编辑链路复现并验证参数冲突、CRLF、截断路径问题。
- TUI 回归覆盖等待后端确认及向用户显示失败，IDE 回归覆盖切换、回滚、恢复与缺失冻结数据。

这些验证不调用用户真实的外部 MCP 或付费模型。仓库中的 dsh/pi 提示词仍是标注来源日期的 peri 适配摘要，不能将它们宣称为上游最新原文或独立的上游执行引擎。
