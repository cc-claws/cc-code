🛑 子 Agent 取消链路（新增原型，对照参考图）

已定方案：① 文案 was stopped by the main Agent； ② 不新增独立工具，扩展现有 Agent 工具的 action 参数（spawn 默认 / stop）； ③ 停止目标用 task_id 精确指认（模型从 spawn 结果 Background task bg-xxx started… 中已拿到该 ID）。

  • 场景 A — 主 Agent 用 Agent(action=stop) 取消（目标形态）：用户自然语言下达 取消厦门的子agent，主 Agent 按 task_id 精确停止， 时间线渲染为 ● Agent(action=stop, task_id=bg-3f9a21c8) + └ 查询厦门天气 · stopped，随后打印 • Agent "查询厦门天气" was stopped by the main Agent，并继续等待剩余任务。
  • 场景 B — 用户按 x 取消（已实现）：抽屉里选中目标行按 x（或 Ctrl+X Ctrl+K 停全部）。停止来源为 user，与 A 的 by the main Agent 区分，便于判断是谁下的手。
  • 场景 C — 取消后回流：剩余任务完成 → • Agent "查询广州天气" finished · 3m 55s → 汇总报告（末尾注明厦门任务已取消、未执行查询）→ ✻ Cogitated for 4m 14s · done 9:43 + ✻ recap:。
  • 场景 D — 现状对比：当前 Agent 工具 schema 无 action / task_id 参数，主 Agent 无法取消任何子任务，只能回复「请用户自行按 x 停止」。此场景标出全部缺口。
  • 实现要点：① schema 增加 action（enum: spawn|stop，默认 spawn）与 task_id，prompt 的 required 随 action 条件化； ② BackgroundTaskRegistry 已有 abort_handle，按 task_id 查表取消； ③ 停止结果需回给模型可读确认，使其能向用户复述；④ was stopped by … 独立文案（区别于 finished/failed）； ⑤ 可选：✻ Waiting for N background agents to finish 计数行。

💡 真实交互机制说明：

  • Prompt 展开模式 (Ctrl+O)：针对用户在主 Agent 视图下快速查阅 Prompt 的需求，提供了两种设计方案：
    • 方案 A (树形向下展开)：保留树形缩进结构，分支下方挂载 └ Prompt: 和指令正文，视觉层级一致。
    • 方案 B (参考图经典卡片)：完全还原您的参考图样式，每个任务独立渲染为 • Agent(...)、└ Backgrounded agent、└ Prompt:，一目了然。
  • 键盘下键进入管理栏：在主会话中按 ↓ 键，焦点无缝下移进入底部 Agent 管理抽屉，游标变为 >。
  • 上下移动与回车切换：在管理栏按 ↑ / ↓ 移动选框。按 Enter to view 立即切换进入该子 Agent 的独立会话视口。
  • 专属视角与定向指令：进入子 Agent 后，输入框顶部变为亮青色线条并浮现 [ 查询天气 ] 标签，输入框占位符变为 > Message @general-purpose...，可以对子 Agent 单独追问。
  • 后台完成回流：子任务完成后自动向主线程上报，主线程展示绿点 • Agent "xxx" finished · 1m 32s 并自动综合输出汇总报告。
